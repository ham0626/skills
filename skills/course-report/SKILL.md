# Course Report（翻转课堂 · 纵深汇报）

## Overview

为课程小组汇报 / 翻转课堂制作"只深挖一个问题是点、不重复课堂内容"的演示。核心是"先定后做"的对齐流程（项目开始前先对齐用户的思路与纠结点）+ 按话题挑选的分析框架（FTA/瑞士奶酪/5M1E 是事故成因类专用镜头，其他课程换通用框架）+ IP 钩子叙事法 + 单文件交互 HTML demo 脚手架与发布流程。目标是把"边做边定"变成"先定后做"，把一次汇报从约 3.5 小时压到 1 小时内。

## When to use

- 用户要做翻转课堂汇报、课程小组展示、课程汇报。
- 明确或隐含约束：时长有限（如 7 分钟）、受众是听过课的同学、要求"纵深一个点 / 一个问题"而非横向铺开课堂内容。
- 触发词：翻转课堂、课程汇报、小组展示、一个点深挖、纵深、不重复上课内容、7 分钟汇报。

## 核心铁律

1. **纵深优先**：只选 ONE 问题点深挖，绝不把课堂内容横向重讲一遍。开工前必须锁死这一点。
2. **载体先定**：交互 / 动画需求强 → 单文件 HTML demo；纯放映 → PPTX。选定后不中途切换（这是历史上最大的返工来源）。
3. **不编造**：数据 / 引用 / 时间线必须来自用户材料或联网核实；无法核实的内容标"需核实"，绝不杜撰。
4. **框架按话题选**：FTA / 瑞士奶酪 / 5M1E 只适用于"事故 / 失效成因"类话题（如实验安全）；其他课程从框架菜单换通用框架（因果链 / 时间线 / 对比 / 系统图等），见 `references/frameworks.md` 的"按话题选框架"。

## 工作流（先定后做）

### 阶段 0 · 约束确认卡（最关键，开工前必做）

**先定后做原则**：拿到 topic 后**先对齐、再执行**，绝不上来就做（历史上最大的返工就来自"边做边定"）。对齐的落点是：把用户的**思路与纠结点**摆到台面上，确认角度、框架适配、载体、视觉后再动手——这是助理在项目开始前的硬责任。

**0.1 摆出用户的思路与纠结点（对齐清单，必做）**
用户给 topic 后，先把以下典型纠结点逐条摆出来确认，尤其红线"会不会又变成横向重讲课堂"：
- **切入点**：topic 太大，从哪个点切？怕选错角度整版推倒。
- **横向红线**：会不会又变成把上课内容铺开？这是用户最在意的红线，任何方案都要先自检"是不是纵深一个点"。
- **载体**：PPT 还是交互网页？中途切换最废时间，必须先定。
- **视觉 / 钩子方向**：主色、暗黑还是亮色、是否用 IP 梗（如生化危机）。
- **专业度 vs 可读性**：术语太多同学听不懂，太少又显得水；平衡点在哪。
- **时长 / 页数**：如 7 分钟讲多少屏、节奏怎么排。
- **框架适配**：本话题适合哪种分析框架？不是默认 FTA（见 `references/frameworks.md` 的"按话题选框架"）。

**0.2 主题与钩子商讨循环**
- 基于上面确认的切入点，提出 **2–3 个"主题切入点 + 钩子"候选**供商讨。
  - 例：本次"生物安全"的候选之一 = 以《生化危机》病毒泄露为钩子切入，再转折到 2004 真实实验室感染事件。
- 用 AskUserQuestion 让用户选方向；可多轮来回，直到主题、钩子、纵深点三方一致。
- 钩子只作开场吸引，正文必须回到**真实、可溯源**的事件。

**0.3 一次性确认其余约束**（用 AskUserQuestion）
- **场景 / 时长 / 受众**（如：翻转课堂 · 7min · 听过课的同学）
- **载体**：单文件交互 HTML demo / PPTX
- **视觉定调**：主色、暗黑 or 亮色、是否用 IP 梗（如生化危机）、参考图
- **纵深锚点**：要深挖的 ONE 问题点 + 真实案例 / 事件（anchor）
- **分析框架**：从菜单按话题选（不是默认 FTA；见 `references/frameworks.md` 的"按话题选框架"）

**0.4 确认门（最后一步）**
- 复述一遍约束卡（主题 / 钩子 / 锚点 / 框架 / 载体 / 时长 / 视觉），等用户说"开始 / 执行"再动手。
- 任何一项未确认，**不进入阶段 1**。

### 阶段 1 · 素材 intake

- 若用户提供云端课件链接：打开并通读，将缩略图备份到 `课件备份/`。
- 提取"课堂已讲过的内容"，明确**不重复**的边界，写进交付说明的遗留清单。

### 阶段 2 · 角度与框架

- 锁定 ONE 纵深点 + anchor 事件（真实、可溯源）。
- **按话题从框架菜单选骨架**（见 `references/frameworks.md` 的"按话题选框架"）：事故成因类用 FTA + 瑞士奶酪 + 5M1E；其他话题用因果链 / 时间线 / 对比 / 系统图等。框架服务于深挖，不是固定套路。

### 阶段 3 · 构建

- **HTML demo 路线**：复制 `assets/demo-template/index.html` 起步（脚手架默认带 FTA 事故树 + 奶酪动画，可换成其他框架），按 `references/html-demo-conventions.md` 实现点击弹题 / 对齐闪烁动画、灯箱放大、灰度底图保证可读性。
- **PPTX 路线**：加载 `workbuddy-pptx` / `ppt-reference`，按纵深结构出页（参考幻灯侠规范）。
- **去专业化**：把过于专业的术语 / 配方替换成口语，但保留关键权威术语，并标注来源（如卫健委摘要、国务院令 424 号）。
- **钩子叙事**：用流行文化钩子（如生化危机病毒泄露）开场抓注意力，再转折到真实事件，制造"现实没有浣熊市，但每次失控都值得认真对待"的落点。

### 阶段 4 · 一回合收敛验收清单

逐项核对，一次交付即达标：

- [ ] 灯箱：画廊图片点击可放大全图
- [ ] 交互/动画：若用了事故树则点节点弹题正常；若用了奶酪动画则对齐 + 警告闪烁正常（按所选框架核对）
- [ ] 可读性：深色背景下文字清晰，底图已做灰度 / 压暗处理
- [ ] 无残留术语：专业串已被口语化或标来源
- [ ] 来源已标：真实事件 / 法规 / 报告有出处
- [ ] 每页有明确目的，总时长与约束吻合（如 7min 约 8–10 屏）

### 阶段 5 · 发布与容灾

- 用 `workbuddy_sites_deploy` 生成对外分享链接（默认**无时效**，可在"设置—数据管理—应用"下线；链接带 `?sharecode=` 访问口令）。
- **容灾**：随时保留 `index.html.bak`；关键改动即存盘；后端断连（如 429 限流 / 强制更新）时优先本地重建入口而非等待。
